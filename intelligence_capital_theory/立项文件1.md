# Intelligence Capital Theory Minimal Formalism

定义：

1. Change Stream
   D = {(o_t, a_t, o_{t+1}, y_t)}

2. Change Event
   e_t = Δ(o_t, a_t, o_{t+1})

3. Throttling Function
   T(D) -> S

4. Stored Information Cost
   Cost(S)

5. Value in New Context
   V(S, C_new)

6. Intelligence Appreciation Rate
   IAR = [V(S, C_new) - V(Baseline, C_new)] / Cost(S)

7. Operational Realization Rate
   ORR = realized_value / predicted_value

8. Bad Debt Ratio
   BDR = shortcut_explainable_gain / reported_gain

必须写清楚：
- RawMemory 是一种高成本资本；
- StateOnly 是 autonomous dynamics shortcut；
- ActionOnly 是 action-main-effect shortcut；
- ResidualCompressor 只有在 residual oracle 已被证明有效后才有意义；
- 如果 residual signal 本身不存在，训练模型没有意义。

============================================================
四、IC-2a：Oracle Residual Accounting Test
============================================================

目标：
先不训练复杂模型。
先证明 action-induced residual 是否真实存在、是否可迁移、是否能超过 StateOnly / ActionOnly。

环境文件：
src/env_structured_volatility.py

实现 StructuredVolatilityEnv。

要求：
环境生成 structured volatility，不是随机噪声。

每个样本包含：
- latent mode m，但不能直接提供给普通模型；
- observable state o；
- short history h；
- action a ∈ {-1, 0, +1}；
- outcome y_H for H ∈ {1, 3, 5}。

环境必须包含以下机制：

1. Autonomous dynamics
   世界自己会动，形成 StateOnly shortcut。

2. Action-effect sign flip
   同一个 action 在不同 hidden mode 下效果符号不同。

3. Delayed consequence
   某些 outcome 依赖过去动作或过去 mode。

4. Counterfactual fork
   对同一个 history h，能够 snapshot/restore，分别执行 -1, 0, +1。

5. Structured OOD
   分三种：
   - OOD_background_shift：只改变背景漂移；
   - OOD_action_gain_shift：只改变动作增益；
   - OOD_sign_rule_shift：改变 action-effect sign rule。

注意：
hidden mode 可以用于生成数据和评估，但模型输入不得直接包含 hidden mode。

八、IC-2b：Learned Throttling Mechanism Test
============================================================

只有 IC-2a 通过才运行 IC-2b。

文件：
src/throttling_mechanisms.py
src/train.py
src/run_ic2b_learned_compressors.py

比较以下 throttling mechanisms：

1. StatePredictor
   学 raw outcome Y。

2. AEPCompressor
   输入 history + action，预测 Y(h,a)。

3. ResidualCompressor
   分解：
   B_hat(h) -> noop outcome
   R_hat(h,a) -> oracle residual
   Y_hat = B_hat + R_hat

4. CenteredResidualCompressor
   预测 CenteredResidual。

5. CounterfactualCompressor
   输入 h，一次输出三个 action outcomes:
   Y_hat(h,-1), Y_hat(h,0), Y_hat(h,+1)

6. CausalContrastCompressor
   用 contrastive loss：
   RealAEP 相似的 histories 拉近；
   RealAEP 不同的 histories 拉远；
   但不能使用 hidden_mode label。

7. ResidualAdversarialCompressor
   在 ResidualCompressor 基础上加入 adversary：
   adversary 试图只用 h 预测 residual；
   主模型通过 gradient reversal 或 adversarial loss 剥离 state-only residual shortcut。

注意：
ResidualAdversarialCompressor 不得直接使用不可信 r_hat 当作唯一监督。
必须同时有 oracle residual / centered residual supervision。

训练目标：
- prediction loss；
- residual loss；
- counterfactual table loss；
- optional contrastive loss；
- adversarial state-only penalty。

============================================================
十四、重要原则
============================================================

不要把理论命名当作实验结果。
ResidualCompressor 这个名字不能证明 residual 是真资产。
必须先由 oracle residual accounting 证明 residual signal 存在。

不要让 hidden_mode 泄漏给模型。
不要让 ActionOnly 靠动作主效应作弊。
不要让 StateOnly 靠 autonomous dynamics 作弊。
不要把 OOD 换 seed 当成真实 OOD。
不要只看 MSE，要看成本、迁移、兑现、坏账。

本项目的最高目标：
不是证明 ICT 一定正确，
而是建立一个能让 ICT 失败的审计系统。
