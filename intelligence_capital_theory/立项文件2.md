# Intelligence Capital Minimal Lab 详细框架

核心目标只有一个：

> **同样一段世界变动流，不同节流机制是否能把原始变动信息转化成可迁移、可兑现、成本有效的智能资本？**

不要急着证明 ICT 正确。
这个项目的真正目标是建立一套能让 ICT 失败的审计系统。

---

# 0. 总体研究逻辑

旧 AEP 项目的问题是：

```text
AEP prediction 成立
≠
AEP control 成立

latent geometry 成立
≠
operational realization 成立

Temporal model 复杂
≠
真正利用时序因果
```

所以新项目不从“模型能不能赢”开始，而从“资本账本是否真实”开始。

总流程：

```text
世界变动流 Change Stream
        ↓
反事实账本 Counterfactual Table
        ↓
Oracle Residual Accounting
        ↓
判断动作残差是否是真资产
        ↓
若通过，再训练 learned throttling mechanisms
        ↓
成本审计 / 迁移审计 / 坏账审计
        ↓
判断是否产生 Intelligence Appreciation
```

也就是：

```text
先证明资产存在
再训练模型去压缩资产
最后审计资产能否迁移和兑现
```

# 2. 理论层框架

## 2.1 核心命题

```text
智能不是即时判断，
而是世界变动信息被采样、压缩、节流、保留后，
在新情境中的增值兑现。
```

也可以写成：

```text
World changes
→ sampled
→ compressed / throttled
→ retained as structure
→ transferred
→ realized as prediction / decision / control value
```

---

## 2.2 基本对象

### Change Stream

```text
D = {(o_t, a_t, o_{t+1}, y_t)}
```

含义：

```text
o_t：当前观测
a_t：动作
o_{t+1}：下一个观测
y_t：后果 / outcome
```

---

### Change Event

```text
e_t = Δ(o_t, a_t, o_{t+1})
```

不是所有时间步都有同等价值。
真正有资本价值的是：

```text
碰撞
反转
延迟后果
动作符号翻转
状态-动作分叉
反事实差异
跨环境仍保留的结构
```

---

### Throttling Function

```text
T(D) → S
```

含义：

```text
从原始变动流 D 中节流出结构 S
```

例如：

```text
RawMemory：几乎不节流，直接保存
StatePredictor：只保存状态动力学
AEPCompressor：保存 action-effect structure
ResidualCompressor：只保存动作造成的偏离
CounterfactualCompressor：保存同状态下不同动作后果
CausalContrastCompressor：只保存会改变未来决策的差异
```

---

### Stored Information Cost

```text
Cost(S)
```

存储成本不能只看模型表现，还要看它用了多少“账面资产”。

神经网络：

```text
参数数量 × 量化 bit
或 compressed checkpoint size
```

RawMemory：

```text
保存的样本数量 × 每条样本字节数
```

PrototypeMemory：

```text
prototype 数量 × 每个 prototype 字节数
```

---

### Intelligence Appreciation Rate

```text
IAR = [V(S, C_new) - V(Baseline, C_new)] / Cost(S)
```

直觉：

```text
同样成本下，
谁在新情境中产生更多价值，
谁的智能增值率更高。
```

---

### Operational Realization Rate

```text
ORR = realized_value / predicted_value
```

用来防止：

```text
预测很好
控制很差
```

如果 ORR 很低，说明只是账面资产，无法兑现。

---

### Bad Debt Ratio

```text
BDR = shortcut_explainable_gain / reported_gain
```

如果模型表现提升大部分都能被 StateOnly / ActionOnly / ShuffledAction / PermutedHistory 解释，那就是坏账。

# 3. 环境层框架

文件：

```text
src/env_structured_volatility.py
```

环境必须是 **structured volatility**，不是随机噪声。

## 3.1 环境必须包含 5 种机制

### 机制一：Autonomous Dynamics

世界自己会动。

例如：

```text
position, velocity 自然演化
存在背景漂移 bg_drift
存在惯性 friction
```

它用于制造 StateOnly shortcut。

目的不是让 StateOnly 赢，而是要审计：

```text
模型到底是在学背景动力学，
还是在学 action-induced residual？
```

---

### 机制二：Action-Effect Sign Flip

同一个动作，在不同 hidden mode 下效果相反。

例如：

```text
mode = +1 时：
  action +1 → outcome 增大

mode = -1 时：
  action +1 → outcome 减小
```

这样 ActionOnly 不能简单学：

```text
+1 总是好
```

---

### 机制三：Delayed Consequence

某些后果依赖过去动作或过去 mode。

例如：

```text
y_t depends on a_{t-3}
y_t depends on mode_{t-2}
```

这用于测试 PermutedHistoryControl。

如果打乱 history 顺序后模型仍然不掉分，说明所谓 temporal capital 是假的。

---

### 机制四：Counterfactual Fork

同一个 history `h`，可以分别执行：

```text
a = -1
a = 0
a = +1
```

得到：

```text
Y(h,-1)
Y(h,0)
Y(h,+1)
```

这是整个项目的核心账本。

没有 counterfactual fork，就无法判断 action-effect capital 是否真实存在。

---

### 机制五：Structured OOD

不能只换 seed。必须拆成三类 OOD：

```text
OOD_background_shift:
只改变背景漂移。

OOD_action_gain_shift:
只改变动作强度。

OOD_sign_rule_shift:
改变 action-effect sign rule。
```

这样才能知道模型在哪种迁移中失败。

# 4. 数据账本框架

文件：

```text
src/counterfactual_table.py
```

## 4.1 Counterfactual Table

对每个 history `h`，生成：

```text
Y(h,-1,H)
Y(h,0,H)
Y(h,+1,H)
```

其中 H 可以是：

```text
H = 1, 3, 5
```

---

## 4.2 三种核心账本

### Outcome Table

```text
Y(h,a,H)
```

真实后果。

---

### No-op Baseline

```text
B(h,H) = Y(h,0,H)
```

表示：

```text
我不动，世界自己会怎样。
```

---

### Oracle Residual

```text
R(h,a,H) = Y(h,a,H) - B(h,H)
```

表示：

```text
动作相对于背景命运造成的偏离。
```

这是 Action-Effect Capital 的核心候选资产。

---

### Centered Residual

```text
CR(h,a,H) = Y(h,a,H) - mean_a Y(h,a,H)
```

表示：

```text
同一状态下，每个动作相对于平均动作后果的差异。
```

它更彻底地去掉 state-only 共同项。

---

## 4.3 DataFrame 字段

```text
state_id
split
horizon
observable_features
history_features
action
outcome
noop_outcome
oracle_residual
centered_residual
best_action_by_outcome
best_action_by_residual
latent_mode_for_eval_only
```

注意：

```text
latent_mode_for_eval_only 只能用于评估，
不能进入模型输入。
```

# 5. IC-2a：Oracle Residual Accounting Test

这是第一阶段。
**不训练复杂模型。**

目标：

```text
先证明 action residual 这笔资产是否真实存在。
```

---

## 5.1 IC-2a 要回答的问题

```text
1. 动作残差信号是否足够强？
2. ResidualOracle 是否超过 StateOnly？
3. ResidualOracle 是否超过 ActionOnly？
4. residual 是否比 raw outcome 更能跨 OOD 迁移？
5. RawMemory 在成本归一化后是否仍然更强？
6. benchmark 是否稳定？
```

---

## 5.2 核心指标

### residual_variance_ratio

```text
Var(R) / Var(Y)
```

判断动作残差在总变化中占多大比例。

死亡条件：

```text
< 0.15
```

说明动作残差太弱，不值得训练模型。

---

### residual_action_separability

```text
mean pairwise distance between:
R(h,-1), R(h,0), R(h,+1)
```

判断同一状态下不同动作的残差是否可区分。

---

### oracle_action_entropy

```text
Entropy(best_action_by_residual)
```

如果 entropy 很低，说明最优动作几乎恒定，ActionOnly 容易作弊。

---

### action_only_ceiling

只看 action 能达到的最优动作预测上限。

如果高，说明动作主效应过强。

---

### state_only_ceiling

只看 observable/history 能达到的上限。

如果高，说明 StateOnly 仍然主导。

---

### residual_oracle_match

ResidualOracle 根据真实 residual 选择动作的 match。

---

### residual_oracle_gain_over_stateonly

```text
ResidualOracle - StateOnly
```

这是 IC-2a 最重要指标之一。

如果它不大于 0，说明 AEP-control 不成立。

---

### transfer_premium

```text
OOD 上 Residual mechanism 相对 baseline 的收益
```

---

### intelligence_appreciation_rate

```text
IAR = transfer_gain / stored_cost
```

---

### bad_debt_ratio

```text
reported gain 中可被 shortcuts 解释的比例
```

---

## 5.3 IC-2a 死亡条件

```text
D1:
residual_variance_ratio < 0.15
=> 动作残差信号太弱。

D2:
ResidualOracle <= StateOnly
=> AEP-control 不成立。

D3:
ResidualOracle - ActionOnly < 0.10
=> 动作主效应作弊。

D4:
OOD_background_shift 中 residual 不优于 raw outcome
=> residual 没有隔离背景漂移。

D5:
seed variance > oracle/model gap / 2
=> benchmark 不稳定。
```

# 7. IC-2b：Learned Throttling Mechanism Test

只有 IC-2a 通过才运行。

目标：

```text
比较不同节流机制是否能把 world change stream 压缩成可迁移、可兑现的智能资本。
```

---

## 7.1 待比较机制

### 1. StatePredictor

输入：

```text
h
```

预测：

```text
Y(h)
```

它是状态预测基线，不是 operational capital。

---

### 2. AEPCompressor

输入：

```text
h, a
```

预测：

```text
Y(h,a)
```

测试普通 action-conditioned outcome prediction。

---

### 3. ResidualCompressor

分解：

```text
B_hat(h) -> no-op outcome
R_hat(h,a) -> oracle residual
Y_hat = B_hat + R_hat
```

必须有 oracle residual supervision。

不能让模型自己乱分账。

---

### 4. CenteredResidualCompressor

预测：

```text
CR(h,a) = Y(h,a) - mean_a Y(h,a)
```

更强地剥离 state-only 共同项。

---

### 5. CounterfactualCompressor

输入：

```text
h
```

一次输出：

```text
Y_hat(h,-1)
Y_hat(h,0)
Y_hat(h,+1)
```

优点是强迫模型看到同一状态下三个 action 后果。

---

### 6. CausalContrastCompressor

用 RealAEP similarity 作为对比学习信号：

```text
AEP 相似的 histories 拉近
AEP 不同的 histories 拉远
```

但不能使用 hidden mode label。

---

### 7. ResidualAdversarialCompressor

在 ResidualCompressor 基础上加入 adversary：

```text
adversary 试图只用 h 预测 residual
主模型要让 residual 表征不能被 state-only shortcut 解释
```

但必须注意：

```text
adversarial loss 不能替代 oracle residual supervision。
```

# 10. 成功标准

一个 throttling mechanism 只有同时满足以下条件，才能说产生了 intelligence appreciation：

```text
1. OOD transfer premium > 0

2. IAR > RawMemoryEqualCost

3. best_action_match > StateOnly + 0.10

4. best_action_match > ActionOnly + 0.10

5. BadDebtRatio < 0.5

6. ShuffledAction 后性能显著下降

7. PermutedHistory 在 delayed task 中显著下降

8. seed variance < model gap / 2
```

缺一条都不能强 claim。

# 11. 失败解释框架

如果失败，不要泛泛说模型不行。必须分类。

## 类型一：Residual asset 不存在

表现：

```text
residual_variance_ratio < 0.15
ResidualOracle <= StateOnly
```

解释：

```text
动作残差本身不是有效资产。
```

---

## 类型二：资产存在，但不能学习

表现：

```text
ResidualOracle 很强
LearnedResidual 很弱
```

解释：

```text
模型或训练目标不能逼近 oracle residual。
```

---

## 类型三：资产能学，但不能迁移

表现：

```text
ID 好
OOD 差
transfer premium <= 0
```

解释：

```text
这是局部记忆，不是结构资本。
```

---

## 类型四：资产能迁移，但成本太高

表现：

```text
transfer gain 有
但 IAR < RawMemoryEqualCost
```

解释：

```text
产生收益，但资本效率不如原始记忆。
```

---

## 类型五：资产是假资产

表现：

```text
StateOnly/ActionOnly/Shuffled/Permuted 接近主模型
BadDebtRatio > 0.5
```

解释：

```text
主要收益来自捷径或泄漏。
```

# 17. 最重要的原则

```text
ResidualCompressor 这个名字不能证明 residual 是真资产。

TransferPremium 这个指标名不能证明真的迁移。

IntelligenceCapital 这个理论名不能证明智能增值。

只有超过 RawMemory、StateOnly、ActionOnly、ShuffledAction、PermutedHistory，
并且成本归一化后仍然有 OOD 收益，
才算真正的 intelligence appreciation。
```

# 18. 这个框架的核心价值

它把你的研究从：

```text
模型有没有学到状态？
```

升级为：

```text
模型是否用有限存储成本，
保留了能跨情境兑现的世界变动结构？
```

这才是“智能资本论”的实验入口。

一句话：

> **IC-2 的目标不是证明某个模型聪明，而是审计：一段世界变动信息，在经过不同节流机制后，究竟有没有形成可迁移、可兑现、成本有效的智能资本。**
